# TTRS · ARENA 50

40줄 스프린트, 2분 타임어택, 최대 50명 온라인 테트리스. 키보드 전용으로 플레이합니다.

## 컨테이너 실행과 종료

Windows의 Docker Desktop(Linux containers / WSL 2)을 실행한 뒤 **프로젝트 폴더**에서 PowerShell 명령을 실행합니다.

```powershell
cd C:\Users\Ch010101\Desktop\TTRS
# 최초 1회: 무작위 DB 비밀번호를 .env에 생성. 기존 .env는 덮어쓰지 않음.
powershell -ExecutionPolicy Bypass -File scripts/setup.ps1
docker compose -p ttrs up -d --build --wait
```

- 첫 입장 화면(로그인 / 회원가입 / 게스트): <http://127.0.0.1:1558>
- 솔로 게임: <http://127.0.0.1:1558/play>
- 대결: <http://127.0.0.1:1558/battle>
- 계정·기록: `/account`, 랭킹: `/rankings`, 플레이 설정: `/settings`
- 외부: `http://서버PC의공인IP:1558/battle` (방화벽과 공유기 포트 전달 필요)

```powershell
# 상태 / 로그
docker compose -p ttrs ps
docker compose -p ttrs logs --tail 100 web
# 종료: DB 데이터는 유지
docker compose -p ttrs down
# 다시 실행
docker compose -p ttrs up -d --wait
# 코드 수정 후 새 이미지 적용 (진행 중 방은 종료됨)
docker compose -p ttrs up -d --build --wait
```

로컬 Python/Uvicorn을 별도로 실행하지 않습니다. 기존 프로세스가 1558 포트를 사용하면 먼저 종료해야 합니다.

### 게임 서버와 DB 분리

| 서비스 | 역할 | 외부 공개 |
| --- | --- | --- |
| `web` | FastAPI + 서버 판정용 Node 엔진 | TCP 1558 |
| `db` | PostgreSQL 17: 계정·세션·플레이 기록·랭킹 원본 | 없음 |

두 컨테이너는 Compose 내부 네트워크로 통신합니다. PostgreSQL의 5432 포트는 호스트에 공개하지 않습니다. DB가 정상 기동된 다음 게임 서버가 시작합니다. 영구 데이터는 `ttrs_postgres-data` 볼륨에 저장됩니다.

**`docker compose down -v`는 DB 볼륨을 삭제하므로 실행하지 마세요.** `.env`는 Git에서 제외되며 비밀번호가 들어 있으니 별도로 안전하게 보관하세요. 기존 DB가 있는 상태에서 `.env` 비밀번호만 변경하면 접속이 실패합니다. 운영 비밀번호 변경은 PostgreSQL 계정과 `.env`를 함께 변경해야 합니다.

컨테이너는 Docker 엔진이 켜져 있어야 실행됩니다. PC 재부팅 후에도 서비스가 필요하면 Docker Desktop의 로그인 시 자동 시작을 활성화하세요. 메모리 상한은 web 1GB, DB 512MB입니다. 실제 50명 서비스 품질은 PC 성능과 업로드 대역폭에 영향을 받습니다.

### 백업

게임 서버와 분리된 DB 컨테이너에서 백업합니다. Windows PowerShell의 바이너리 리다이렉션을 피하도록 컨테이너 안에서 파일을 만든 뒤 복사합니다.

```powershell
docker compose -p ttrs exec -T db pg_dump -U ttrs -d ttrs -Fc -f /tmp/ttrs-backup.dump
docker compose -p ttrs cp db:/tmp/ttrs-backup.dump ./ttrs-backup.dump
```

백업 파일에는 계정 및 세션 정보가 포함됩니다. 외부에 공유하거나 Git에 추가하지 마세요. 복원은 기존 DB 덮어쓰기를 피하도록 별도 PostgreSQL DB에 `pg_restore --no-owner`로 복원·검증한 뒤 전환하는 것을 권장합니다.

## ARENA 50

1. 첫 화면에서 로그인·회원가입 또는 게스트 입장을 선택합니다. 게스트는 중복되지 않는 `guest_숫자5~6자리` 닉네임으로 입장합니다. 초대 링크로 접속하면 입장 후 방 코드가 유지됩니다.
2. 방 이름을 입력해 만들고 6자리 코드 또는 초대 링크를 공유합니다. 이름이 비어 있거나 공백뿐이면 `닉네임s_room`으로 자동 생성됩니다. 방 목록에서도 참가할 수 있습니다.
3. **방장 외 참가자 한 명 이상 준비하면 방장이 시작**할 수 있습니다. 방장에게는 준비 버튼이 없으며, 시작하면 준비 여부와 관계없이 현재 방의 인원 모두 3초 카운트다운 후 동일한 7-bag 순서로 대결합니다. 방장이 나가면 남은 첫 참가자가 방장이 됩니다.
4. 내 화면은 솔로와 같은 HOLD·보드·세로 NEXT 5개입니다. 다른 모든 참가자는 **격자·고스트 없는 작은 보드**로 표시됩니다. 특정 공격 대상 하나만 표시하지 않습니다.
5. 보드가 넘치거나 기권·방 나가기·연결 종료 시 탈락합니다. 마지막 생존자가 승리합니다. 탈락 후에도 방 안에서 전체 보드를 관전하고 채팅할 수 있습니다.
6. 결과 후 참가자 한 명 이상 다시 준비하고 방장이 시작하면 재대결합니다. 진행 중인 방에는 새로 참가할 수 없습니다.

### 공격

| 공격 | 쓰레기 줄 |
| --- | --- |
| 싱글 / 더블 / 트리플 / 테트리스 | 0 / 1 / 2 / 4 |
| T스핀 싱글 / 더블 / 트리플 | 2 / 4 / 6 |
| 미니 싱글 / 더블 | 0 / 1 |
| B2B / 퍼펙트 클리어 | +1 / +10 |
| 연속 2~3 / 4~5 / 6~7 / 8회 이상 삭제 | +1 / +2 / +3 / +4 |

내 공격은 받을 공격부터 FIFO 순서로 상쇄합니다. 남은 공격 묶음은 **공격할 때마다 다른 생존자 한 명을 무작위로 골라** 보냅니다. 자기 자신·탈락자는 제외하며, 전체에게 복제하거나 특정 상대에게 고정하지 않습니다. 같은 상대가 연속으로 뽑힐 수 있습니다.

보드 옆 20칸 세로 표시와 보드 안 예고선으로 총 대기 공격줄 높이를 표시합니다. 노란색은 예고 중, 빨간색은 예고 완료입니다. 20줄 초과 시 보드 높이까지만 채우고 실제 줄 수를 표시합니다. 보드 크기를 조정해도 높이는 줄 단위로 비례합니다.

1.2초 예고 후 줄을 지우지 않은 착지에서 한 번에 최대 8줄이 올라옵니다. 줄 삭제 시 상승을 유예하며, 한 공격 묶음은 같은 구멍을 공유합니다. 대기 공격은 플레이어당 최대 100줄입니다. 서버가 모든 대결 입력·공격·승패를 판정합니다.

### 채팅과 크기 조절

- 보드 기본 너비 300px, 채팅 기본 높이 300px, 사이드 영역 너비 300px를 유지합니다. 별도 조절 버튼 없이 **보드·채팅의 좌우/아래 가장자리나 오른쪽 아래 모서리를 마우스로 드래그**합니다. 보드는 1:2 비율을 유지하며 220~420px, 채팅은 높이 180~650px·너비 260~480px 범위로 조정합니다. 드래그 중 키 입력은 해제되지만 게임은 계속 진행됩니다. 좁은 화면에서는 겹치지 않도록 영역이 아래로 이동합니다.
- 크기는 브라우저에 저장됩니다. `Enter`로 채팅 입력, `Escape`로 입력창을 벗어납니다. 웃는 얼굴 버튼에서 이모티콘 16종을 선택합니다.
- 방 전용 채팅 200자 / 최근 100개, 메시지 간 최소 0.5초. 채팅과 크기 조절 중에도 게임은 계속됩니다.
- 터치·클릭 이동/회전/낙하 버튼은 제거했습니다. 메뉴·설정·채팅은 마우스로 조작할 수 있습니다.

## 계정, 기록과 랭킹

- 게스트도 DB 기록과 랭킹에 참여합니다. 기존 한글 게스트는 새 입장 화면에서 입장 시 사용자 ID와 기록을 유지하면서 숫자 닉네임으로 전환됩니다. 게스트 상태에서 회원가입하면 같은 사용자 ID와 기록을 유지합니다. 기존 다른 계정으로 로그인하면 기록을 합치지 않습니다.
- 게스트는 쿠키에 연결됩니다. 쿠키 삭제/만료 또는 로그아웃 후에는 기존 게스트 기록에 다시 접근할 수 없으므로, 보관할 기록이 있으면 회원가입하세요.
- 비밀번호는 무작위 salt를 포함한 PBKDF2-SHA256 600,000회로 해싱합니다. 세션은 불투명한 HttpOnly/SameSite 쿠키이며 DB에는 토큰의 SHA-256만 저장합니다. 변경 요청은 CSRF 토큰과 동일 출처를 확인합니다.
- **현재 공인 IP HTTP 접속은 전송 암호화가 없습니다. 공개 계정 서비스로 운영하기 전 HTTPS 프록시를 구성하고 `.env`에 `COOKIE_SECURE=true`를 설정하세요.** WebSocket은 HTTPS에서 WSS로 연결됩니다. 다른 서비스와 동일한 비밀번호를 사용하지 마세요.
- 솔로 신규 플레이는 서버가 발급한 seed와 입력 로그를 같은 엔진으로 재생해 시간·점수·종료 상태를 검증합니다. 클라이언트가 보낸 점수만 믿고 저장하지 않습니다. 이는 완전한 봇/치트 방지 시스템은 아닙니다.
- 완주/게임오버 기록을 저장합니다. R로 중단한 판은 저장하지 않습니다. 오프라인·긴 백그라운드 중단·입력 로그 한도 초과·검증 실패 시 로컬 기록만 남고 화면에 이유를 알립니다.
- 서버 랭킹: **40줄 완주 최단 시간**, **2분 완주 최고 점수**, **대결 누적 생존 포인트(참가 인원 − 최종 순위)**. 대결 동점은 우승 횟수 순이며 무승부는 우승으로 계산하지 않습니다. 계정별 상위 100명과 개인 최근 100판을 표시합니다.
- 기존 브라우저 최고 기록/최근 기록은 그대로 보존하지만 검증할 수 없는 과거 기록을 서버 랭킹으로 가져오지는 않습니다. 로컬 타임어택 최고 점수는 기존처럼 조기 종료도 포함합니다.

## 기존 솔로 규칙과 설정

40줄 스프린트와 120초 타임어택을 유지합니다. 낙하 속도는 항상 1초에 1칸이며 빨라지지 않습니다. 7-bag, SRS, 홀드, T스핀/미니, 콤보, B2B, 퍼펙트 클리어, 500ms 잠금 지연(최대 15회 갱신)을 지원합니다.

`A`키는 전용 180도 킥으로 L/J 틈 넣기 등을 처리합니다. 90도는 SRS, 180도는 기존 osk 킥 테이블을 유지합니다. 별도 L/J/S/Z/I 스핀 점수는 추가하지 않습니다.

`/settings`: DAS/ARR, 고스트(기본 선명도 55%), 보드 격자·배경, 효과·사운드, 젤리/모찌/크리스탈/네온/레트로 5개 스킨. 저장 전 미리보기와 기본값 복원을 지원하고, 새 탭에서 저장하면 기존 게임 탭에도 반영됩니다.

## 운영 범위

- 한 방 최대 50명, 전체 접속 최대 256개, 최대 64개 방. 같은 사용자로 대결 탭을 중복 연결할 수 없습니다.
- 방과 채팅은 메모리 상태입니다. **서버 재시작 시 진행 중인 방은 사라지며 완료되지 않은 판은 기록하지 않습니다.** 계정과 이미 저장된 기록은 DB 볼륨에 유지됩니다.
- 재접속 시 진행 중인 게임 복구는 지원하지 않습니다. 네트워크 단절은 대략 20초 이내에 탈락 처리됩니다.
- 방 상태는 단일 Node 엔진에 있으므로 **Uvicorn worker 하나**를 유지하세요. 여러 web 복제본을 띄우는 분산 서비스 구성은 지원하지 않습니다.

## 테스트

테스트 계정과 랭킹을 운영 데이터에 섞지 않도록 **별도 Compose 프로젝트/볼륨**을 사용합니다.

```powershell
$env:TTRS_PORT='1559'
$env:TTRS_BIND='127.0.0.1'
docker compose -p ttrs-preview up -d --build --wait
docker compose -p ttrs-preview exec -T web python -m pytest -q -p no:cacheprovider
docker compose -p ttrs-preview exec -T web node --test "tests/*.test.cjs"
docker compose -p ttrs-preview exec -T -e TTRS_ALLOW_LOAD_TEST=true web python tests/live_arena.py

# 실제 Chrome 입력/Canvas/UI 검증: 호스트의 Node 22+ 및 Chrome 필요
$env:TTRS_URL='http://127.0.0.1:1559'
node tests/arena-browser.cjs
node tests/entry-browser.cjs
node tests/settings-browser.cjs
node tests/battle-browser.cjs
node tests/browser.cjs

docker compose -p ttrs-preview down
Remove-Item Env:TTRS_PORT,Env:TTRS_BIND,Env:TTRS_URL
```

단위/API 테스트는 임시 SQLite로 격리하며, `live_arena.py`와 브라우저 테스트는 실제 PostgreSQL과 50개 WebSocket을 검사합니다. 솔로 기존 UI 회귀 테스트의 인위적 보드 배치는 로컬 검증 전용이며, `arena-browser.cjs`에서 실제 키보드 플레이의 서버 기록 저장을 따로 검증합니다. Chrome 테스트는 독립 프로필을 사용하고 캡처는 `.test-artifacts/`에 저장합니다.
